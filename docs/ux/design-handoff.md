# CREAI+IT HR — 디자인팀 목업 제작 전달서

2026-09-26 · 검토용 v1 · [사용자 경험 설계안](experience-design.md)과 함께 사용

## 1. 의뢰 내용

**구직자가 자신의 상황에 맞는 공고를 찾아 이유와 확인할 조건을 이해하고, 외부 AI에서 준비를 시작하는 경험**을 클릭 가능한 목업으로 제작한다. 사용자에게 노출되는 제품명은 `CREAI+IT HR`로 통일한다.

전체 기능 구현, 실제 크롤링·DB 연결·LLM 호출은 이번 제작에 포함하지 않는다. 샘플 데이터와 정해진 대화 분기로 상호작용을 구현한다. Figma라면 화면 전환·variants·변수로, 웹 프로토타입이라면 로컬 fixture로 같은 동작을 만든다. 제작 도구와 무관하게 아래 사용자 경험 계약을 유지한다.

확정된 이용자는 구직자다. 기업 채용 담당자 화면, 회원가입·프로필 작성, 이력서 업로드, 직접 지원, 알림 구독, 유료 결제는 그리지 않는다.

## 2. 반드시 전달할 제품의 차이

1. **말로 설명해도, 조건을 골라도 같은 탐색으로 이어진다.** 직무명에 익숙하지 않은 사람과 빠르게 검색하려는 사람을 모두 지원한다.
2. **추천 이유와 확인할 부분이 같이 보인다.** 공고의 사실, 사용자 정보, 미확인을 구분한다.
3. **결정 다음의 준비가 이어진다.** 공고와 맥락을 다시 복사하지 않고 준비 프롬프트를 가져간다.

교육 유입은 이 경험을 해치지 않는 보조 행동이다. 채용 결과를 보장하거나 AI를 써야만 탐색할 수 있는 제품처럼 보이게 하지 않는다.

## 3. 산출물과 화면 목록

디자인 파일의 섹션은 `01 사용자 여정`, `02 핵심 화면`, `03 상태·반응형`, `04 클릭 시연` 네 개로 구성한다. 첫 페이지에 아래 프레임 인덱스와 시작 링크를 둔다.

| ID | 화면군 | 필요한 기본 프레임 | 연결되는 행동 |
|---|---|---|---|
| S00 | 시작 | 첫 방문, 조건으로 시작, 자유 입력 | 탐색, 공고 상세 |
| S01 | 탐색 | 첫 결과, 조건 수정 후 결과, AI 패널 접힘, 미확인 후보 그룹 | 필터, 상세, 저장, 비교 |
| S02 | 조건 편집 | 기본 필터, 상세 조건, 필수·선호 편집, 변경 취소 | 적용 후 S01, 취소 후 기존 상태 |
| S03 | 상세 | 맥락 있는 진입, 공고 링크 직접 진입, 근거 펼침 | 원문, 준비, 저장, 탐색 복귀 |
| S04 | 비교 | 2개, 3개, 후보 교체 | 상세, 준비, 제거 |
| S05 | 준비 프롬프트 | 목적 선택, 개인 맥락 포함 전·후, 전체 프롬프트, 복사 성공·실패 | 복사, 상세 복귀, 선택적 교육 안내 |
| S06 | 저장한 공고 | 빈 목록, 저장 목록, 변경·마감·확인 지연, 개별 삭제·전체 기록 삭제 | 상세, 비교, 탐색 복귀 |

**반응형 기준:** 핵심 화면은 1440px 데스크톱과 390px 모바일로 제작한다. 1024px에서 대화 패널이 접히는 방식과 360px에서 긴 제목·하단 행동이 겹치지 않는 것도 보여준다. 모든 상태의 모든 해상도를 별도 프레임으로 중복 제작할 필요는 없고, 핵심 전환이 실제로 읽히는 상태를 우선한다.

## 4. 레이아웃과 화면 연결 규칙

### 데스크톱 탐색 화면

```text
┌ CREAI+IT HR ───── 기회 찾기  저장한 공고 ───── CREAI+IT 소개 ┐
│ [상황 또는 키워드]                          [기회 찾기]     │
│ [서울 · 필수] [신입 · 필수] [분석 업무 · 선호] [조건 편집]  │
├─────────────┬─────────────────────────────────────────────┤
│ 탐색 도우미 │ 조건에 맞는 공고                  [정렬]    │
│ 현재 기준  │ 회사 · 직무                       [저장]    │
│ 짧은 대화  │ 실제 업무 / 근무 조건 / 마감                 │
│ 질문 하나  │ 맞는 이유 / 확인할 부분 / 출처        [비교] │
│             │ ...                                         │
│ [대화 입력]│ 추가 확인이 필요한 공고                      │
├─────────────┴─────────────────────────────────────────────┤
│ 2개 선택                                      [비교하기] │
└───────────────────────────────────────────────────────────┘
```

도우미를 접어도 칩과 목록은 남는다. 비교 선택 막대는 후보를 선택했을 때만 보인다. 상세는 별도 화면으로 이동한다. 채팅·목록·상세·필터를 모두 독립 열로 늘리지 않는다.

### 모바일 탐색 화면

```text
브랜드 / 저장한 공고
상황 입력 또는 검색
현재 조건 요약 + 조건 편집
[공고] [조건·대화]
결과 또는 같은 탐색의 대화
선택한 공고가 있을 때만 비교 행동
```

탭 전환으로 조건·대화·스크롤을 잃지 않는다. 대화에서 결과를 갱신하면 `공고 2개 보기`를 제공하며 자동으로 탭을 바꾸지 않는다. 결과가 0개라면 `조건 다시 살펴보기`를 제시한다.

### 링크와 뒤로가기

- 홈 → 탐색 → 상세 → 준비가 기본 흐름이다. 준비 닫기 → 동일 상세, 상세 뒤로가기 → 이전 조건·정렬·스크롤.
- 상세 직접 진입에서도 원문·준비·저장을 쓸 수 있다. 개인화 이유는 `내 조건으로 살펴보기`를 선택한 뒤 나타난다.
- 원문 이동은 실제 제품에서 새 탭이다. 목업에서는 샘플임이 표시된 `원문 예시` 프레임으로 연결하며 실제 채용 사이트에 지원하거나 정보를 전송하지 않는다.
- 교육 링크 역시 목업에서는 목적지가 무엇인지 보여주는 프레임으로 연결한다. 실제 교육 신청 완료를 흉내 내지 않는다.
- 저장한 공고와 일반 목록은 같은 상세로 연결한다. 저장 진입이면 뒤로가기는 저장 목록이다.

## 5. 샘플 데이터 — 모든 화면이 같은 값을 사용

**아래 기업·공고·급여·일정·본문은 전부 목업용 합성 데이터다. 실제 채용 정보가 아니다.** 실제 서비스 로고·채용 후기와 섞어 실재하는 공고처럼 보이게 하지 않는다. 데모 화면 상단에 `샘플 데이터로 보는 UX 목업`을 표시한다.

시연 기준 시각은 **2026-10-06 10:00 KST**로 고정한다. 시연 날짜가 지나도 자동으로 모든 샘플을 마감시키지 않는다. 날짜 계산은 고정된 시연 시각으로 한다. 아래 `확인`은 가상의 마지막 본문 확인 시각이다. 게시일이 없는 공고에 그 날짜를 게시일로 표시하지 않는다.

| F12 | 확인 가능한 업무 본문 없음 | 미확인 | 원문 근거 없음. 제목을 바탕으로 자세한 업무·자격을 생성하지 않음 |

### 5.3 변형 데이터

- **V1 내용 변경:** 저장했던 F01 v1은 주 3일·10/22 마감. 재방문 시 F01 v2는 주 5일·10/12 마감. 두 값의 차이를 표시한다. 주 3일 필수인 사람의 저장 목록에서 공고를 자동 삭제하지 않는다.
- **V2 마감:** 재방문 시 F03 원문이 명시적으로 마감됐고 F11도 같은 상태로 확인됐다고 설정한다. 해당 묶음은 마감 구역으로 이동.
- **V3 갱신 실패:** F06의 마지막 성공 기록은 유지하고 이후 확인에 실패했다는 상태만 추가한다. 임의로 마감·무효가 되지 않는다.
- **V4 출처 충돌:** F06에 동일 모집 ID를 가진 두 번째 출처가 존재하되 연봉이 4,500~6,000만원으로 다르게 적혀 있는 변형. 기본 데이터에는 추가하지 않고 X14 시연 때만 사용한다. 연봉 5,000만원 필수 충족으로 확정하지 않는다.
- **V5 경력직 범위 부족:** 경력직 샘플을 실제 확보 데이터로 바꾸는 상황을 가정해 F06·F07을 결과로 내지 않는다. X04의 커버리지 제한 문구를 표시한다. 경력직이 존재하지 않는다고 단정하지 않는다.

## 6. 클릭 가능한 시연 시나리오

### D1 · 첫 인턴 탐색 → 확인할 조건 → 경험 정리

1. S00: 사용자가 “수업에서 산업 자료를 조사하고 정리해봤어요. 서울에서 리서치 경험을 쌓을 인턴을 찾고 있어요” 입력 → S01.
2. 도우미: “시장 조사·자료 정리 업무를 중심으로 찾았어요. 근무 가능한 요일이나 기간이 정해져 있나요?” 동시에 F01·F02를 보여준다. 질문 답변은 건너뛸 수 있다.
3. 사용자: “학기 중이라 주 3일만 가능해요.” → `서울 · 필수`, `인턴 · 필수`, `주 3일 · 필수`, `리서치 · 선호` 표시.
4. 결과: F01은 조건에 맞는 후보, F02는 근무일 확인 필요. `주 3일 조건을 적용했어요 · 되돌리기` 표시. 이 시연에서는 두 공고만 노출한다.
5. F02 상세에서 근무일 미기재 확인 → 돌아가기 → F01 상세 → 저장.
6. 준비하기 → `내 경험 정리하기` → 대화에서 말한 수업 경험이 보이지만 포함 체크는 기본 꺼짐. 그대로 두고 전체 프롬프트 확인 → 복사 성공.
7. 복사된 텍스트에는 개인 경험이 미제공으로 표시되고, 경험을 묻도록 요청한다. 대화의 수업 경험을 몰래 포함하거나 가짜 인턴 경험을 만들지 않는다.

**검토 질문:** F02는 왜 확정 추천이 아닌가? 직무명을 몰라도 시작할 수 있었는가? 복사한 내용으로 어떤 대화를 시작할 수 있나?

### D2 · 필터 탐색 → 비교 → 지원 전략

1. S00에서 자연어 입력 없이 서울·정규직·신입 필터, 업무에 데이터 분석 선택 → S01.
2. F03/F11 묶음과 F04 노출. 선택한 지역·고용 형태·신입 조건은 확인됐지만 사용자 경험은 미입력이므로, F03은 `SQL 경험 확인 필요`, F04는 `Excel 경험 확인 필요`로 추가 확인 그룹에 둔다. F05는 부산·경력 필수로 제외한다. 마감·일정 경과 후보를 정상 추천에 섞지 않는다.
3. F03과 F04의 비교 선택 → S04. F03 `SQL 필수`와 F04 `SQL 우대`가 나란히 읽혀야 한다.
4. F03 상세 → `이 공고 준비하기` → `지원 전략 세우기`.
5. 경험 “수업 프로젝트에서 SQL로 고객 구매 데이터를 분석했다” 입력. 포함 체크를 켠 뒤 미리보기 확인.
6. 복사 → 원문 예시 프레임 → 돌아와도 F03 상세와 검색 조건 유지.
7. 이 여정은 복사와 원문 확인으로 완료된다. 교육 연결을 검토하는 별도 분기에서는 사용자가 “AI를 활용한 실제 업무 경험도 만들어보고 싶다”고 추가 입력한 뒤, 복사 성공 아래에 보조 안내를 노출한다. 교육을 누르지 않아도 여정은 완료된다.

**검토 질문:** 필수와 우대의 차이를 설명할 수 있나? 공고 두 출처가 두 채용 자리로 오해되지 않는가? AI 대화 없이도 목적을 달성했나?

### D3 · 선택적 이직 → 미확인 조건 → 저장·재방문

1. S00에서 “서울에서 제품 운영 경력 3년을 살릴 일을 보고 있어요. 연봉 5천 이상과 주 2일 재택은 꼭 필요해요” 입력.
2. S01에 F06과 F07 표시. F06은 관련 조건 확인, F07은 연봉·재택 미확인. 현재 회사명을 묻지 않는다.
3. S02에서 지역은 필수, 제품 개선 업무는 선호임을 확인하고 취소해 기존 조건 유지.
4. F07 상세 → 미공개 조건 확인 → F06·F07 저장 → S06 이동. `이 브라우저에 저장됩니다` 안내.
5. 시연 도구로 재방문 V3 적용 → F06 확인 지연 표시. 이전 정보의 시각이 남아 있어야 한다.
6. 별도 분기로 V5 적용 → 경력직 수집 범위 부족 상태. 사용자에게 “당신에게 맞는 일자리가 없다”고 말하지 않는다.

**검토 질문:** 희망 연봉이 충족되는지 모르는 후보를 구분하는가? 저장이 다른 기기로 이어질 것이라고 오해하는가? 정보 공개 없이 이용 가능한가?

### D4 · 직무 전환 → 경험 연결 → 조건 보완

1. S00: “영업 운영을 1년 했고 Excel과 CRM으로 고객 데이터를 정리했어요. 데이터 쪽 업무로 옮겨보고 싶어요.”
2. S01: F04를 먼저 제시하고 F03을 SQL 경험 확인 필요로 표시. F05는 필수 경력에 알려진 불일치가 있어 기본 추천에서 제외.
3. F04 카드 이유: “고객 데이터 정리·운영 지표 업무가 입력한 경험과 연결돼요.” 이는 동일 직무 경력을 인정한다는 의미가 아니다.
4. F03 상세: “SQL 활용 경험은 공고상 필수예요. 해당 경험은 아직 입력되지 않았어요.” → 사용자에게 경험 보완 선택 제공.
5. 사용자가 “SQL은 아직 안 써봤어요”를 선택 → F03은 알려진 필수 불일치로 표시. 현재 상세는 유지하고 목록 추천에서는 제외한다.
6. F04로 돌아가 `내 경험 정리하기` → 사용자 경험 포함 여부 선택 → 복사.

**검토 질문:** 기존 경험과 연결되는 이유를 이해하는가? 미입력과 미충족의 차이가 보이는가? 막연한 합격 약속 없이 다음 준비가 명확해지는가?

### D5 · 재방문과 실패 회복

1. 별도 시작 프레임에서 F01·F03을 저장한 상태로 진입. 현재 세션에는 자료 조사·정리 경험과 서울·리서치 인턴·주 3일 필수 조건을 미리 설정한다. D1~D4와 섞이지 않도록 `재방문 시연`이라고 표시.
2. V1과 V2 적용 → F01의 근무일·마감 변경, F03 명시적 마감 확인.
3. F01은 저장 목록에 유지. 상세에서 주 3일 필수와의 불일치를 표시.
4. 새로운 탐색에서 주 2일·서울·리서치 인턴 조건 → X03. 확인된 일치 결과는 0건이며 F02는 근무일 미확인으로 별도 표시한다. F01 v2를 근거로 `주 5일도 검토할까요?`라고 제안하되, 선택 전에는 필수 조건과 0건 표시를 유지한다.
5. 사용자가 `주 5일로 변경`을 명시적으로 선택 → F01 v2가 후보로 나타난다. 상세·저장 목록 모두 주 5일·10/12 마감으로 일치한다. 제안 거절 분기에서는 주 2일 조건을 유지한다.
6. X09 AI 오류 → 기본 필터로 F04 상세 진입 → 프롬프트 복사 X10 실패 → 전체 텍스트 수동 선택.

**검토 질문:** 실패 상황에서 어디로 갈지 알 수 있나? 데이터 버전과 마감이 서로 모순되지 않는가? AI가 없어도 무료 기본 경험이 남아 있나?

## 8. 재사용 컴포넌트와 문구

| 컴포넌트 | 필수 variants | 문구·행동 기준 |
|---|---|---|
| 탐색 입력 | 빈 값, 입력 중, 전송 중, 오류 | 한글 입력 중 Enter로 조기 전송되지 않게 고려. 버튼으로 확정 가능 |
| 조건 칩 | 필수, 선호, 미확정 제안, 삭제 | 사용자 조건을 한눈에 복기. 제안은 적용된 조건과 다르게 표시 |
| 공고 카드 | 일반, 개인화, 미확인, 마감, 확인 지연, 저장됨 | 정보 순서 고정. 출처·확인 시각 생략 금지 |
| 근거 항목 | 충족 근거, 정보 부족, 알려진 불일치 | 세 상태 모두 텍스트 라벨. 숫자 적합도·합격률 없음 |
| 비교 막대 | 1개, 2~3개, 선택 없음 | 선택 없음이면 숨김. 최대 개수 명확 |
| 토스트·상태 안내 | 저장, 복사, 변경, 오류 | 저장·복사 성공은 실제 동작 성공 후. 변경에는 되돌리기 |
| 원문·교육 외부 이동 | 정상, 샘플 대상 | 목적지 명확. 원문 이동이 지원 완료는 아님 |
| 빈 결과 | 조건 불일치, 데이터 범위 부족 | 설명과 회복을 구분. 무조건 전체 조건 초기화 금지 |

사용자 화면의 `agent`, `semantic matching`, `token`, `revision`, `parser`, `Neon` 같은 구현 용어는 `탐색 도우미`, `맞는 이유`, `내용 변경`, `확인 지연`으로 바꾼다. 상태를 설명하는 데 필요한 정보까지 모호하게 숨기지는 않는다.

색·폰트·간격 등 시각 토큰은 CREAI+IT 기존 브랜드 자산을 확인해 제안한다. 지금 기본 Next.js 화면의 스타일을 완성된 브랜드 시스템으로 간주하지 않는다. 장식 이미지·큰 모션보다 공고 정보와 비교 가독성에 제작 시간을 우선 배정한다.

## 9. 제작 완료 체크리스트

- [ ] D1~D5 시작 링크가 있고, 클릭 가능한 끝점까지 끊기지 않는다.
- [ ] 입력 예시를 선택한 뒤 수정할 수 있고, 필터만으로도 탐색한다.
- [ ] 모바일 `공고` / `조건·대화`가 같은 조건·후보를 유지한다.
- [ ] 개인화 이유를 읽고 원문 근거로 이동할 수 있다.
- [ ] 필수 조건 미확인과 알려진 불일치가 다르게 보인다.
- [ ] 목록의 공고 수와 fixture 수가 일치하고 F03·F11을 중복 채용으로 세지 않는다.
- [ ] 마감된 F08, 일정 경과 F09, 갱신 실패 F10을 구분한다.
- [ ] 저장·비교·상세·준비를 왕복해도 조건과 스크롤을 잃지 않는다.
- [ ] 프롬프트에는 공고·출처·확인 시각·미확인 항목이 있고, 동의한 개인 맥락만 포함한다.
- [ ] 복사 실패·저장 실패·AI 오류에서도 다음 행동이 있다.
- [ ] 같은 화면에서 샘플 버전 v1/v2가 섞이지 않는다. 시연 초기화는 명시적이다.
- [ ] 초점 이동·키보드·확대·작은 모바일 폭에서 핵심 행동을 수행한다.
- [ ] 교육을 누르지 않아도 준비 여정을 완료한다. 개인정보·구직 맥락을 교육 사이트로 자동 전달하지 않는다.
- [ ] 화면별로 ‘동작을 검토할 수 있는 부분’과 ‘아직 fixture로 대체된 부분’을 전달한다.

## 10. 디자인 리뷰 진행안

처음에는 D1과 D2를 설명 없이 수행하게 한다. 그다음 D3·D4에서 조건과 미확인의 이해를 확인하고, D5에서 회복을 확인한다. 참가자가 막히면 클릭 위치를 알려주기보다 “지금 무엇을 기대했나요?”라고 묻는다.

리뷰 기록은 `과업 → 멈춘 화면 → 사용자의 기대 → 실제 반응 → 수정 필요성` 다섯 항목으로 남긴다. 우선 수정할 문제는 잘못된 지원 가능 판단, 잃어버린 입력·조건, 원문·복사로 진행할 수 없는 막힘이다. 시각적 취향은 그다음에 조정한다.

목업 승인 기준은 [설계안의 열 가지 기준](experience-design.md#13-목업-검토를-통과하는-기준)을 실제 시연에서 확인하는 것이다.
