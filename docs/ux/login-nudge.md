# CREAI+IT HR — 로그인 유도(넛지) 설계안

2026-09-27 · 검토용 v1 · [사용자 경험 설계안](experience-design.md)의 "가입 없음·브라우저 저장만" 원칙을 "선택 계정"으로 바꾸는 제안

**로그인은 목적이 아니라 수단이다. 사용자가 모은 것을 잃고 싶지 않거나, 다른 기기에서 이어가고 싶거나, 놓치고 싶지 않은 순간에만 그 필요를 해결하는 방법으로 제안한다.**

전제: 탐색·상세·원문 확인·준비 프롬프트·이 브라우저 저장은 계속 로그인 없이 쓴다. 교육 소식 수신 동의는 로그인과 분리한다(6절). 이 문서의 법적 사항은 일반 원칙 수준이며 실제 문구·절차는 법무 확인이 필요하다.

## 1. 출발점

### 1.1 사용자는 로그인을 원하지 않는다

사용자가 원하는 것은 아래 네 가지이고, 로그인은 그 대가다. 넛지는 "로그인하세요"가 아니라 이 중 하나를 그 순간에 제안하는 것이다.

| 사용자가 원하는 것 | 그 욕구가 생기는 순간 | 로그인으로 해결되는 것 |
|---|---|---|
| 모은 것을 잃지 않기 | 공고를 두세 개 저장했을 때, 공용 PC·시크릿 창을 쓸 때 | 계정에 보관 |
| 다른 기기에서 이어 보기 | 휴대폰에서 찾고 PC에서 자세히 읽을 때(P1) | 기기 간 동기화 |
| 놓치지 않기 | 저장한 공고의 마감이 다가오거나 내용이 바뀔 때, 결과가 0건일 때 | 마감·변경·새 공고 알림 |
| 같은 말을 반복하지 않기 | 두 번째 공고를 준비하며 경험을 다시 적을 때(P2) | 내 경험 저장 후 재사용 |

"로그인하면 추천이 더 정확해져요"처럼 실제로 로그인과 무관한 이점은 약속하지 않는다.

### 1.2 우리가 얻고 싶은 것과 지켜야 할 것

- **얻고 싶은 것:** 다시 돌아오는 사용자(계정), 교육 소식을 받겠다는 명시적 동의.
- **지켜야 할 것:** 가입 없는 첫 이용, 마케팅 동의의 분리(개인정보보호법상 선택 동의, 동의 거부를 이유로 서비스 거부 불가), 재직자의 노출 우려(P3), 무료 서비스에 대한 신뢰.

두 목표는 서로 다른 순간에 다룬다. 로그인은 "내 것을 지키는" 순간에, 교육 동의는 "AI 역량에 관심이 생긴" 순간에 받는다.

## 2. 설계 원칙

1. **필요가 생긴 뒤에, 그 필요를 해결하는 말로.** 버튼 문구는 "로그인"이 아니라 "마감 전에 알림 받기", "다른 기기에서도 보기"다. 로그인은 그다음 단계로 나온다.
2. **하던 일을 끊지 않는다.** 저장은 로그인 없이도 항상 성공한다. 넛지는 작업의 경계(저장 직후, 복사 성공 후, 목록 끝, 결과 0건)에만 나온다.
3. **사실을 먼저 말한다.** "이 브라우저에만 저장돼요"라는 정직한 한계 안내가 넛지의 출발점이다. 불안을 키우는 과장("지금 안 하면 모두 사라져요")은 쓰지 않는다.
4. **거절이 쉬워야 한다.** "나중에"는 같은 자리에 같은 무게로 둔다. 거절은 기억하고 다시 조르지 않는다. "아니요, 기회를 놓칠래요" 같은 거절 문구는 쓰지 않는다.
5. **관련성은 높아지고 압박은 높아지지 않는다.** 사용자가 더 많이 모을수록 제안이 구체적이 될 뿐, 빈도·크기·색은 커지지 않는다.
6. **로그인하고 돌아오면 하던 일이 이미 끝나 있다.** "알림 받기"를 눌러 로그인했다면 돌아왔을 때 알림이 켜져 있고, 브라우저에 모은 공고와 조건은 자동으로 계정에 옮겨져 있다.
7. **약속은 실제 기능만.** 넛지에 적는 이점은 모두 로그인 후 바로 쓸 수 있는 기능이어야 한다.

## 3. 넛지의 강도 단계

| 단계 | 형태 | 나오는 조건 | 예 |
|---|---|---|---|
| L0 입구 | 헤더의 조용한 "로그인" 텍스트 버튼, 저장한 공고 하단 링크 | 항상 | — |
| L1 사실 한 줄 | 상태 안내에 붙는 한 줄 + 텍스트 링크 | 사용자가 방금 한 행동의 결과로 | 첫 저장 알림 |
| L2 인라인 제안 | 콘텐츠 흐름 안의 작은 카드, "나중에" 포함 | 필요가 쌓였을 때, 세션당 1회 | 저장한 공고 상단 |
| L3 로그인 시트 | 계정이 있어야 하는 기능을 사용자가 직접 눌렀을 때만 열림 | 사용자의 명시적 요청 | 알림 받기, 모든 기기에서 기억, 경험 저장 |

**L4(요청하지 않은 모달, 결과 가리기, 기능 차단)는 쓰지 않는다.**

시각 규칙: 넛지는 주요 행동 색(로열 솔리드)을 쓰지 않는다. 흰 판과 아쿠아 선, 텍스트 링크로 표현해 사용자의 과업 버튼보다 항상 한 단계 약하게 보이게 한다.

### 쓰지 않는 패턴

첫 방문 모달, 원문·프롬프트를 로그인 뒤로 숨기기, "로그인하고 결과 더 보기", 이탈 감지 팝업, 카운트다운·가짜 희소성, 거절을 부끄럽게 만드는 문구, 미리 체크된 마케팅 동의, 약관 "전체 동의"에 마케팅 포함, 거절 후 반복 노출, 저장 버튼을 누르면 로그인부터 요구, 가입 때 전화번호·이력서·학교 요구.

## 4. 로그인을 제안할 순간

| ID | 화면 | 트리거 | 사용자의 속마음 | 보여줄 것 | 강도 | 노출 규칙 |
|---|---|---|---|---|---|---|
| N1 첫 저장 | S01·S03 | 비로그인 상태의 첫 저장 성공 | "일단 모아두자" | 알림: "이 브라우저에 저장했어요. **다른 기기에서도 보기**" | L1 | 최초 1회 |
| N2 모인 후보 | S06 | 저장 2개 이상인 상태로 저장한 공고를 엶 | "후보가 쌓이고 있다" | 상단 카드: "휴대폰과 PC에서 같은 목록을 보고, 마감 전에 알림도 받을 수 있어요." [카카오로 계속하기] [이메일로 계속하기] [나중에] | L2 | 세션 1회, 나중에 → 14일 숨김 |
| N3 마감·변경 알림 | S06 카드, 저장된 공고의 S03 | 사용자가 "마감 전 알림" 버튼을 누름 | "이건 놓치면 안 된다" | 로그인 시트: "마감 3일 전과 내용이 바뀔 때 알려드릴게요" | L3 | 요청할 때마다. **핵심 전환 지점** |
| N4 새 공고 알림 | S01 결과 0건(X03), 범위 부족(X04), 목록 끝 | 사용자가 "이 조건으로 새 공고 알림"을 누름 | "지금은 없지만 생기면 알고 싶다" | 버튼은 L1 수준으로 조용히 노출, 누르면 로그인 시트 | L1 → L3 | 막다른 길을 돌아올 이유로 바꾼다 |
| N5 경험 재사용 | S05 | 두 번째 준비에서 경험을 다시 입력하고 복사함 | "또 써야 하네" | 복사 성공 아래 한 줄: "방금 쓴 경험을 저장해 두면 다음 준비에서 바로 불러와요 **경험 저장하기**" | L1 → L3 | 두 번째 준비부터 1회. 저장 전 내용을 보여주고 확인 |
| N6 기기 이동 | 모바일 S03 | 모바일에서 두 번째 상세를 열거나 본문을 끝까지 읽음 | "PC에서 제대로 보고 싶다" | "PC에서 이어 보기" [링크 복사] [로그인하고 목록으로 보기] — 로그인 없는 대안을 먼저 | L1 | 세션 1회 |
| N7 조건 기억 | S02 | "이 브라우저에 조건 기억"을 켬 | "다음에도 이 조건으로" | 스위치 아래 한 줄: "휴대폰에서도 기억하려면 **로그인**" | L1 | 켤 때만, 수동적 |
| N8 재방문 | S00·S01 | 브라우저에 기록이 있는 재방문 | "지난번 거 어디 있지" | "지난번 조건으로 이어 보기"(로그인 불필요). 로그인 제안은 하지 않음 | — | 로컬로 먼저 가치를 보여준다 |

### 우선순위

N3과 N4가 가장 좋은 순간이다. 사용자가 먼저 원하는 기능을 눌렀고(방해 비용 0), 그 기능은 계정 없이는 실제로 불가능하기 때문이다(정직함). N2는 가장 많은 사용자가 보게 될 제안이고, N5는 P2의 "매번 자기소개하는 피로"를 직접 해결한다. N1·N6·N7은 입구를 알려주는 역할로만 둔다.

### 넛지를 보이지 않는 상태

첫 방문에서 첫 결과를 보기 전, 입력 중, 결과를 찾는 중, 시트가 열려 있을 때, 비교 중, 준비 프롬프트를 복사하기 전, 오류 직후. 이 상태에서 조건이 충족돼도 경계가 올 때까지 보류하고, 경계를 지나치면 버린다(나중에 몰아서 보여주지 않는다).

## 5. 로그인 시트

### 5.1 구성

1. **맥락 제목** — 트리거가 된 필요를 그대로 쓴다.
   - N3 "마감 전에 알려드릴게요" · N4 "새 공고가 생기면 알려드릴게요" · N2·N1·N6 "어느 기기에서든 같은 목록" · N5 "다음 준비에서 바로 불러오기"
2. **옮겨지는 것** — "이 브라우저에 저장한 공고 3개와 탐색 조건을 계정으로 옮겨요." 실제 항목과 개수를 보여준다. "대화와 경험 서술은 옮기지 않아요"도 함께 적는다.
3. **방법** — [카카오로 계속하기] [이메일로 계속하기(메일로 받은 링크로 로그인, 비밀번호 없음)]. 전화번호·이력서·학교·현 직장은 묻지 않는다.
4. **신뢰 한 줄** — "공개 프로필이 없어요. 기업이나 다른 사람은 내 정보를 볼 수 없어요." 재직자(P3)의 망설임을 직접 다룬다.
5. **동의** — 필수 항목(이용약관, 개인정보 수집·이용, 만 14세 이상 확인)만 받는다. 교육 소식은 이 시트에서 묻지 않는다(6절).
6. **닫기** — 닫으면 원래 화면 그대로다. 저장한 공고와 조건은 브라우저에 그대로 남는다.

### 5.2 로그인 직후

- 원래 화면으로 돌아오고, 요청했던 일이 끝나 있다(N3이면 알림 켜짐, N5면 경험 저장 확인 화면).
- 알림: "저장한 공고 3개를 계정으로 옮겼어요. 휴대폰에서도 같은 목록을 볼 수 있어요."
- 다른 기기에서 로그인하면 양쪽 기록을 합친다. 한쪽에만 있는 공고를 지우지 않는다.
- 헤더의 "로그인"은 이니셜 메뉴가 되고, 메뉴에는 알림 설정·내 데이터·로그아웃이 있다. 로그인한 사용자에게는 넛지를 보이지 않는다.
- "내 데이터"에서 계정에 저장된 항목을 확인하고 전체 삭제·탈퇴할 수 있다. 공용 기기 사용자를 위한 "이 브라우저의 기록 지우기"는 그대로 둔다.

### 5.3 계정에 저장하는 것

| 항목 | 저장 | 비고 |
|---|---|---|
| 저장한 공고 ID, 마지막으로 확인한 버전 | 저장 | 변경 알림에 필요 |
| 구조화된 탐색 조건(꼭/선호 포함) | 저장 | 조건 재사용 |
| 알림 설정(종류·채널) | 저장 | |
| 동의 기록(항목·문구 버전·시각·채널) | 저장 | 법적 근거, 2년 재확인 |
| 경험 서술 | 사용자가 "경험 저장하기"를 눌렀을 때만 | 민감 정보. 저장 전 내용 확인, 언제든 삭제 |
| 도우미와의 대화 | 저장하지 않음 | |

## 6. 교육 소식 동의는 따로

로그인 넛지에 섞지 않는다. 채용 정보를 지키려고 로그인한 순간에 광고 동의를 붙이면, 무료 서비스가 "가입시켜 광고를 보내는 곳"으로 읽힌다.

- **제안 시점:**
  - (a) 준비 프롬프트 복사 성공 후, AI로 실제 업무 경험을 만들고 싶다는 맥락이 있을 때(기존 교육 안내 블록).
  - (b) 교육 소개 링크를 눌렀다 돌아왔을 때 1회.
  - (c) 알림 설정 화면에서 언제든.
- **보여줄 내용:** 무엇을(CREAI+IT 교육·행사 안내, 광고성 정보), 얼마나 자주(월 N회 이하, 정해야 함), 어디로(이메일 또는 카카오), 어떻게 끄는지(언제든, 모든 메시지 하단 수신 거부).
- **형태:** 기본 꺼짐, 단독 체크, "전체 동의"에 포함하지 않는다. 동의하면 기록을 남기고 2년마다 동의 여부를 다시 확인한다. 야간(21~08시)에는 보내지 않는다.
- **서비스 알림과 섞지 않는다:** 마감 알림 메일에 교육 광고를 끼워 넣지 않는다. 동의한 사람에게도 별도 메시지로 보낸다.

| 알림 | 성격 | 필요한 것 |
|---|---|---|
| 저장한 공고의 마감 임박·내용 변경 | 서비스 알림(사용자가 켠 것) | 계정 + 알림 설정 |
| 내 조건에 맞는 새 공고 | 서비스 알림 | 계정 + 알림 설정 |
| CREAI+IT 교육·행사 안내 | 광고성 정보 | 선택 수신 동의 + 채널 |

### 채널에 대한 현실적인 기대

웹 서비스의 푸시는 도달이 제한적이다. 아이폰은 홈 화면에 추가한 웹앱에서만 웹 푸시를 받고, 안드로이드·PC도 브라우저 권한을 따로 받아야 한다. 초기에는 이메일(가장 저렴)로 시작하고, 도달률이 문제가 되면 카카오 메시지를 검토한다. 웹 푸시는 권한 요청 자체가 거슬릴 수 있어 "알림 받기"를 누른 사용자에게만 채널 선택지 중 하나로 제안한다.

## 7. 노출 규칙(넛지 예산)

- 한 화면에는 넛지 하나만 보인다.
- 요청하지 않은 넛지(L1 알림, L2 카드)는 세션당 하나.
- "나중에"를 누른 넛지는 14일 동안 숨긴다. 서로 다른 넛지를 세 번 거절하면 30일 동안 L2를 숨기고 L0·L3만 남긴다.
- 첫 방문에서 첫 결과를 보기 전에는 어떤 넛지도 없다.
- 로그인한 사용자에게는 넛지가 없다. 알림 채널 권한 요청은 알림을 켤 때만 한다.
- 넛지 노출·거절 기록은 이 브라우저에만 저장하고, 개인 맥락을 담지 않는다.

## 8. 여정별 흐름 예시

- **P1 첫 인턴 탐색(휴대폰 → PC):** 첫 방문 탐색 중 넛지 없음 → F01 저장 시 N1 한 줄 → 두 번째 상세에서 N6 "PC에서 이어 보기"(링크 복사 선택) → 다음 날 PC에서 저장한 공고를 열자 N2 카드 → 카카오로 계속하기 → 휴대폰에서 모은 목록은 없지만 PC 목록이 계정으로 옮겨짐. 휴대폰에서 로그인하면 합쳐짐.
- **P2 목표가 명확한 지원자:** 첫 준비에서는 넛지 없음 → 두 번째 공고 준비에서 경험을 다시 적고 복사하자 N5 → 경험 저장하기 → 로그인 시트 → 돌아오면 저장할 경험 확인 화면.
- **P3 선택적 이직:** F06·F07 저장, 넛지는 N1 한 줄뿐 → F06 상세에서 "마감 전 알림"을 누름 → 로그인 시트의 "공개 프로필이 없어요"를 확인하고 이메일로 계속하기.
- **결과 0건(X03·X04):** "이 조건으로 새 공고 알림"(N4) → 로그인 → "조건에 맞는 공고가 들어오면 이메일로 알려드릴게요".

## 9. 측정과 가드레일

| 보는 것 | 지표 |
|---|---|
| 전환 | 넛지별 노출 대비 로그인 완료율, 로그인 사용자의 7·30일 재방문 |
| 기능 가치 | 알림을 켠 사용자 수, 알림을 받고 돌아온 비율, 경험 재사용 횟수 |
| 피로(가드레일) | 넛지 닫기 비율, 넛지 직후 이탈, 원문 이동·프롬프트 복사율 변화, 저장 해제 |
| 교육 | 맥락별 수신 동의율, 교육 메시지 클릭률, 수신 거부율 |

**로그인 수만 늘고 원문 이동·복사율이 떨어지면 넛지가 과한 것이다.** 이 경우 L2부터 줄인다.

## 10. 결정이 필요한 것

1. 로그인 방법: 카카오 + 이메일 링크(권장), Google 추가 여부.
2. 알림 채널: 이메일로 시작(권장) 또는 처음부터 카카오 메시지.
3. 로그인 없이 이메일만으로 교육 소식을 받게 할지.
4. 교육 소식 빈도 약속(월 몇 회 이하).
5. 경험 저장의 허용 범위와 보관 기간.
6. 만 14세 미만 사용자 처리(가입 제한 또는 법정대리인 동의).

## 11. 기존 문서와 목업에 반영할 것

- 경험 설계안 1.3·3.4·9절과 S06: "계정·기기 간 동기화 제외"를 "선택 계정"으로 바꾼다. 가입 없는 첫 이용 원칙은 유지한다.
- 디자인팀 전달서: 제외 범위의 "회원가입·알림 구독"을 목업 포함으로 옮기고, N1~N7과 로그인 시트·알림 설정 화면을 프레임 목록에 추가한다.
- 목업: 가짜 인증으로 N1~N7, 로그인 시트(맥락 제목·옮겨지는 항목·신뢰 문구), 로그인 후 합치기 알림, 헤더 이니셜 메뉴, 알림 설정(서비스 알림·교육 소식 분리)을 구현하고, 시연 도구에 "로그인 상태"와 "넛지 거절 기록 초기화"를 추가한다.
