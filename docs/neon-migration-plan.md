# Neon 수집 저장소 전환

2026-09-26. SQLite의 다섯 수집 파일을 Neon의 `hr` 스키마로 합친다. 스케줄러와 LLM 호출은 범위 밖이다.

| 테이블 | 한 행의 의미 | 보존 이유 |
|---|---|---|
| source_postings | 한 출처의 한 공고에 대한 최신 상태 | `(source, tenant_key, source_id)` 중복 방지, 다음 상세 확인과 짧은 작업 임대 관리 |
| posting_revisions | 실제 내용·기간·상태가 달라진 한 버전 | 이후 스냅샷 한 개와 변경 필드만 보존. 이전 값은 앞 버전으로 조회 |
| analysis_tasks | 특정 공고 내용과 분석기 버전에 대한 분석 작업 | 불변 revision 참조, 본문 재복사 없음. 재시도·결과·완료 기록 |
| ingest_runs | 한 번의 탐색 또는 갱신 실행 | 범위·진행·부분 실패 근거를 보존 |

`schema_migrations`는 업무 데이터가 아닌 SQL 적용 이력이다. 원문 HTML·전체 응답 로그·반복된 동일 스냅샷은 적재하지 않는다. 공개 공고를 임의로 플랫폼 간 합치지 않는다.

- PostgreSQL의 제약조건과 행 잠금으로 최신 상태·revision·분석 등록을 함께 커밋한다. 늦은 응답은 최신 상태를 덮지 못한다.
- 목록은 페이지 단위 일괄 UPSERT. 상세 작업과 분석 작업은 짧은 트랜잭션으로 임대하고, 네트워크·모델 처리 중 DB 잠금을 유지하지 않는다. 임대 토큰으로 이전 작업자의 쓰기를 차단한다.
- 현재 본문은 JSONB에, 조회·대기열 조건은 타입 있는 열과 좁은 B-tree 인덱스에 둔다. 사용하지 않는 GIN·벡터·회사 마스터·파티션을 먼저 만들지 않는다.
- SQLite 원본은 읽기 전용. 중복 공고를 묶고 관측 시각순 이력을 가져온다. 기존 Neon 레코드는 덮어쓰지 않고 동일 데이터인지 검증한다. 재실행은 건너뛰며, 다른 내용이면 중단한다.
- Neon WebSocket Pool을 사용한다. 로컬 TCP 연결은 reset되지만 공식 드라이버의 HTTPS/WebSocket 접속은 검증됐다. 풀 크기 4, 스키마를 명시한 SQL, 트랜잭션 단위 잠금으로 PgBouncer와 호환한다.
- 검증: 실제 PostgreSQL의 중복·수정·부분 실패·rollback·동시 쓰기·임대 회수·분석 입력 고정, SQLite 합치기/재실행, 10,000건 제한 부하와 인덱스 실행계획, 세 플랫폼의 실제 소량 수집.
